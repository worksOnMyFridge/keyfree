# Policy contract versions

Finding ids: F1..F20 and N1..N17 are the two security reviews in [AUDIT.md](../AUDIT.md). The live policy
`policy13.keyfree-lab.testnet` runs v16; earlier versions ran on earlier testnet accounts (see `spikes/`).

| Version | What changed |
|---|---|
| v1 | The contract builds an EIP-1559 contract-creation transaction from fields, checks it against the owner's rules (allowed code hash, allowed chain, gas caps, its own nonce), asks NEAR MPC to sign its own build and returns the signed raw transaction. It never signs a hash it is given; the chain id is inside the signature. |
| v2 | After the first review: the ETH address is derived on chain from the MPC, never taken from a caller (F11); the signing callback never panics, so a bad MPC answer cannot freeze the contract (F2); a nonce stays bound to one content, so after a failed or late answer only the same deploy can be re-signed with new fees (F5); a request stuck past the MPC timeout can be released by the owner or the agent. |
| v3 | Deploys go through the owner's own CREATE2 factory, which only this contract's address may call, so nobody can take a planned address first (F9). A journal line per nonce is confirmed by NEAR Read MPC from the factory's `Deployed` log, bound with `expected_payload_hash` (F7). |
| v4 | Maintenance without keys: the owner proposes a new code hash, a public delay runs, the guardian can cancel, then the contract deploys the matching code onto itself (same account, so the same ETH address). Pause is immediate; unpause only by the owner. |
| v5 | A late MPC answer can leak a valid signature for a stuck request, and that transaction may land. Then the factory's `Deployed` log for that exact request proves the nonce was used, and `confirm_stuck` clears the request and moves the nonce on. |
| v6 | A signed transaction the chain refuses (gas below the intrinsic minimum, fee too low) would leave a nonce gap forever. The contract refuses gas limits below the intrinsic minimum (EIP-2028, EIP-3860, EIP-7623), and `resign` re-signs a signed factory deploy with the same nonce and content, only gas and fees change. |
| v7 | After the second review (N3-N5): `next_nonce` never moves back; a failed or released re-sign opens nothing; a new request never takes a nonce that already has a journal line; one (salt, code) pair binds to one nonce per chain, so a `Deployed` log can prove only its own nonce; `confirm_stuck` is for the agent or owner and needs a Safe or Finalized block. New state layout, deployed fresh. |
| v8 | Roles (N1): owner, guardian and reserve form a council of three, plus an agent. Brakes are immediate and need one member: pause, revoke the agent. Everything that widens rights waits the full delay and cannot be shortened, even by two members together. A new owner, guardian or reserve needs 2 of 3 approvals, and cancelling it also 2 of 3, so a stolen guardian key cannot block its own replacement. A new agent is proposed by the owner and any member may cancel it. Unpause needs 2 of 3 votes. All four roles are different accounts. |
| v9 | No side doors (N7-N9): a salt goes only through the council's factory (the shared CREATE2 proxy is gone); `allow_chain` only opens a new chain, so the nonce never moves by hand; each chain has a fee floor; `resign` works for any signed line, a plain creation too. |
| v10 | The guardian sees the code it may veto (N6): the owner puts the new wasm itself into the contract state when proposing (storage paid by the attached deposit); the delay starts only then; anyone can read the bytes and check their sha256 against a build of the published source; `apply_upgrade` deploys exactly the stored bytes. |
| v11 | Rules: widening a rule (code on the allow list, a new or re-enabled chain, a factory, higher caps) is an owner proposal that waits `rules_delay_sec`, and any council member may cancel it; narrowing (remove code, disable a chain, remove a factory, lower caps) is a brake: one member, at once. A disabled chain keeps its nonce, so turning it back on can never reset the nonce (N8). |
| v12 | Callbacks read their answer as raw bytes (N13): no answer, however odd, panics. |
| v13 | Retire: a keyless account cannot be deleted by anyone but itself, so the council can retire the policy (2 of 3 and the full delay). Then it is paused for good, `sweep()` empties the state in portions (all growing collections are iterable) and `finish_retire()` deletes the account, sending its NEAR to a council member who approved. `apply_upgrade` keeps the proposal until `migrate` has run (N17). |
| v14 | Proxy upgrades (the treasury scenario): besides deploys the policy signs exactly one kind of call, `upgradeTo(implementation)` on an ERC-1967 proxy whose admin is the policy's address. The council allows one (chain, proxy, implementation) through the rules delay; the contract builds the calldata itself; the allowance is used up by the request, so the same upgrade or a rollback needs a new rule. Read MPC confirms the proxy's `Upgraded` log. New state goes at the end; `migrate` reads the v13 layout. Installed on the live policy without a key. |
| v14.1 | No change in behaviour. The first reproducible build: `cargo near build reproducible-wasm` in a Docker image pinned by digest (`Cargo.toml`), crate renamed `keyfree-policy`, Rust 1.97.1, comments in English. Installed on the live policy without a key on 2026-11-01. |
| v15 | A daily budget per chain (R8, review finding N10): the most gas the policy may commit in one UTC day, counted as gas limit x max fee of every signature (re-signs and retries included, nothing given back), and how many transactions it signs. A budget is set or raised by a rule through the delay (`SetBudget`), lowered at once by any council member (`lower_budget`); `get_budget` shows today's use. `migrate` reads the v14 layout. Installed on the live policy without a key on 2026-11-01. |
| v16 | After the third security review (AUDIT.md, X1-X12): retiring no longer deletes the account, so its name and the MPC-derived EVM address can never be taken by its parent (X1); `confirm_stuck` takes the policy's own signature as seen on chain, rebuilds the transaction and uses its hash, and needs a Finalized block (X2, X6); `retry` and `resign` obey every brake (X4); `confirm` needs Safe or Finalized (X6); `get_open` names the chain (X10). Installed on the live policy without a key on 2026-11-01. |

v1 to v14 were built on a laptop; their bytes carry that machine's paths and cannot be rebuilt elsewhere.
From v14.1 on, `cargo near build reproducible-wasm` gives the live bytes (README, "Check which code the live
policy runs").
