Keyfree · your own policy on testnet

Run your own policy

Paste your contract, pick chains and limits. You get the code hash your policy's allow list must hold, a ready setup/config.json, and the exact commands in order. Everything is computed in this page: it asks for no key and makes no network request at all.

Testnet only. The guardian and the reserve should be accounts you create on other devices, not on the machine where the agent runs. Before real money this needs a professional audit (SECURITY.md lists the known limits).

1 · Your contract

Creation bytecode followed by the ABI-encoded constructor arguments, exactly what the deploy transaction carries.

Artifact JSON

Foundry out/X.sol/X.json or a Hardhat artifact. The file is read in this page and goes nowhere.

2 · Who decides and where

Account names are NEAR testnet ids (lowercase letters, digits, -, _, .; 2 to 64 characters; ending in .testnet). The setup script creates the policy and the agent as sub-accounts of the owner, so both names must end in .<owner>. The guardian and the reserve must already exist.
